# CALG Detector and SDF Contact Snapshot Exports

These files are one-step geometry snapshots from the current C++ backend. The
export is intentionally limited to the three data groups needed for explaining
the local projection plane and height-field construction:

1. original mesh patches, stored separately for the two contacting objects;
2. the AABB boxes associated with those mesh patches;
3. the contact points detected by the SDF response stage.

Selected frames:

| Case | Step | Time (s) | File prefix |
|---|---:|---:|---|
| Guide slot | 2835 | 1.4175 | `guide_slot_cpp_step2835_guide_track_detector_snapshot` |
| Ball-and-socket pendulum | 6184 | 1.2368 | `deep_ball_joint_pendulum_mesh_cpp_step6184_finite_socket_inner_detector_snapshot` |
| Bearing raceway, inner side | 5000 | 2.5000 | `bearing_rotating_inner_cpp_step5000_bearing_inner_detector_snapshot` |
| Bearing raceway, outer side | 5000 | 2.5000 | `bearing_rotating_inner_cpp_step5000_bearing_outer_detector_snapshot` |

Each contact-region prefix contains:

| Suffix | Content |
|---|---|
| `_terrain_patch.vtp` | fixed object original local mesh patch |
| `_body_patch.vtp` | moving object original local mesh patch |
| `_terrain_aabb.vtp` | AABB boxes for the fixed-object patch primitives |
| `_body_aabb.vtp` | AABB boxes for the moving-object patch primitives |
| `_sdf_contact_points.vtp` | SDF response contact points with `gap`, `normal`, `normal_lambda`, `normal_force`, and `area_weight` point data |
| `_index.csv` | one-row manifest linking the files above |

The 2D projection-plane figures are generated by
`scripts/make_detector_snapshot_figures.py` and written to
`paper/figures/detector_snapshots/projection_planes`. For each contact region,
the script estimates the contact center `x_c` from the SDF contact points,
averages their normals to obtain the projection normal `n`, defines the local
plane `Pi: (x - x_c) . n = 0`, and projects the two object patches to local
coordinates `(xi_1, xi_2)`. The signed height used by the height-field
interpretation is `h = (x - x_c) . n`.

These snapshots are not additional dynamics results. They are only geometry
exports for documenting how the contact region is projected before evaluating
the local signed-gap response.
